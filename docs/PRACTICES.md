# Backend practices — Being Lillian API

Short rules. Encode them in FastAPI; do not treat this as optional docs.

## Trust boundary

- `SUPABASE_SERVICE_ROLE_KEY` lives only in the FastAPI host env. Never in Next, never in the browser.
- The frontend only knows `NEXT_PUBLIC_API_URL`. It never talks to Postgres directly in production.
- CORS allowlist: production frontend origin (+ localhost in dev). Reject other origins.

## HTTP contract

- Version public routes under `/v1/...`.
- OpenAPI is generated by FastAPI (`/docs` in non-production only).
- Pydantic v2 models must match SDS enums:
  - `service_type`: MUA | Brand_Collab | Event | General
  - `status`: New | Contacted | Quoted | Booked | Completed | Legacy
  - `category` (posts): Motivation | Self_Promotion | Reviews | Journey_POV
  - `category` (portfolio): MUA_Clients | Photoshoots | Events | Testimonials

## Auth

- Public: `GET /v1/posts`, `GET /v1/posts/{slug}`, `GET /v1/portfolio`, `GET /v1/settings`, `POST /v1/leads`, `GET /v1/auth/status`.
- Admin session: `POST /v1/auth/signup` (first user or when `AUTH_ALLOW_SIGNUP=true`), `POST /v1/auth/login`, `GET /v1/auth/me`.
- Admin APIs require `Authorization: Bearer <JWT>`. Studio JWTs are HS256 with `AUTH_JWT_SECRET`. Supabase Auth JWTs are also accepted when `SUPABASE_JWT_SECRET` is set.
- Passwords are bcrypt-hashed and stored under `data/users.json` in local mode (never commit this file).
- Fail closed on auth errors (401). Rate-limit auth and lead endpoints by IP.
- Never expose lead listing without admin JWT.

## Leads

- Validate: non-empty `full_name`, dialable phone (digits, optional `+`, min length).
- Rate-limit `POST /v1/leads` by client IP.
- After insert, the frontend may open `wa.me` — that is not a substitute for storing the row.

## Migrations

- One SQL file per change under `supabase/migrations/`.
- Do not edit live tables by hand in Studio for schema. Seed data may use `seed.sql`.

## Ops

- Never log JWTs, service role keys, or full phone numbers beyond what support requires.
- Health: `GET /health` returns 200 without DB; `GET /health/ready` reports mode and counts.
- Fail closed on admin auth errors (401/403).

## CRM writes (audit trail)

- Status changes on leads append a note/timestamp. Do not silently overwrite history.
- Admin PATCH should record who changed what when JWT subject is available.
